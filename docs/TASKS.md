# 幸福工厂生产统计 Mod Agent 执行任务

本文件用于将 [产品与技术规划](PLAN.md) 交给后续 agent 实现。本轮不启动开发 agent，不创建占位插件。已确认：先单人再联机；游戏／SML 使用最新稳定发布；通过 ficsit.app 的 SMM 管理；GitHub 公开开源；目前没有 Windows 编译和实机验证机器。

## 1 执行总规则

1. 每项任务读取当前仓库指令，使用 ponytail full。代码检索优先 codegraph，失败后使用 rtk；不自行初始化／重建 codegraph 索引。
2. 先读 PLAN.md 对应章节与前置任务证据，再追踪实际调用链、线程、生命周期和统计边界。未知 API 不按名字猜测。
3. 用最少的原生机制完成任务，不建立通用服务框架，不增加只为测试存在的生产抽象。数据逻辑的可运行检查必须使用实际实现，不能另写一份 Python／JavaScript 算法代替 C++ 验证。
4. 每个 agent 只修改约定负责范围。共享类型、插件描述、构建配置和根资产由单一整合 agent 管理，提出修改建议后由其合入。
5. Unreal `.uasset` 为二进制资产，同一时间只能由一个 agent 编辑。不要把不存在的资产路径、空 `.uasset` 或 JSON 描述当成已创建的 UMG／输入资产。
6. 通过可用 Unreal Editor／受支持工具生成必要资产，提交真实资产及必要源文件。无编辑器时可交付源码与资产创建说明，但该项保留待验证状态。
7. 依赖尚未通过时，只做明确标注的静态调查／独立准备；禁止用 mock 数据宣布真实采集完成。静态、编译、游戏运行三类证据分开记录。
8. 保留用户文件；不以完成任务为由升级整个工具链或擅自扩大统计范围。版本升级只在对应任务中统一进行。
9. 每个任务结束给出变更文件、验证命令与结果、未验证项及下一步阻塞点；没有命令可运行就直说。

任务文档内的源文件路径是责任范围建议，T00 创建真实插件后由整合 agent 统一替换为实际路径，不为满足目录结构而制造空文件。

## 3 任务卡

### T00A 最新发行和环境资料基线

**负责范围：** `docs/ENVIRONMENT.md`，必要的构建说明；不下载整个定制引擎、不创建云资源。

**工作：**

- 查阅官方游戏发行记录与 SML Releases，记录查询日期、最新稳定版本、游戏 build、SML tag／commit、Starter Project 版本和兼容证据。
- PLAN.md 当前候选是游戏 1.2.4.0／502094 与 SML 3.12.0；正式执行时重新核对，不能只复制这些值。
- 确认对应定制 UE、MSVC／其他工具链、Wwise 和 Alpakit 要求，列出需要用户账号访问的资源及真实缺项。
- 列出最短环境取得路径：可用 Windows 开发机优先；适配 Linux 路径需单独核实；不假设 macOS 能直接完成游戏构建。
- 区分“资料已核对”“文件已取得”“编译已通过”“游戏已运行”四种状态。
- 记录GitHub公开仓库的账号／组织、仓库名和许可证是否已指定；缺少时列为待补，不猜测用户名或替用户选择许可证。拟定仓库包含内容与依赖获取边界。

**验收：** 环境文档能让下一 agent 准确知道使用什么版本、从哪里获取、缺什么；没有伪造构建成功。T00A 可独立完成，T00B 仍未完成。

### T00B 工程和空插件加载

**负责范围：** 实际 Starter Project 接入、插件描述、构建规则、根模块／Game Feature 资产、必要忽略规则、ENVIRONMENT.md 中命令。

**工作：**

- 在兼容环境中使用配套模板创建 C++＋内容插件；先验证项目规定的 Game Feature／模块注册方式。
- 固定 Mod Reference；插件名称、版本、SML 依赖及游戏兼容字段按当前 Alpakit 规范填写，保持以后能经 SMM 分发。
- 编译 Editor 和目标游戏配置，Alpakit 打包空插件并在游戏加载；不修改游戏／SML 头文件解决私有访问。
- 保留原始参考图片；工程组织只采用模板要求的结构，不提交引擎、构建缓存或本机安装路径。
- 建立Git仓库与必要忽略规则；用户确定归属、名称、许可证且访问可用后创建公开GitHub仓库并添加真实LICENSE。此项可独立于构建进行；公开推送前按PLAN第8节只纳入可公开的项目文件，参考图保留本地。建库不要求重复确认开源意图。

**验收：** 干净构建成功，日志能证明插件加载，启动／加载／退出不崩溃；提供精确命令和构建机信息。未得到配套机器时本任务必须保持阻塞。

### T01 实际采集可行性与覆盖探针

**负责范围：** 最小诊断采集代码、`docs/API_EVIDENCE.md`；探针放在最终采集层附近，验证后可复用或删除，不建立另一个产品。

**输入：** T00 版本基线，PLAN.md 第4节。

**工作：**

- 优先查已有实际计数／delegate，再评估 hook。为每个候选给出头文件、函数签名、调用时机、线程、单位、成功判断、父／子类覆盖、世界销毁行为。
- 建立覆盖矩阵：采矿／抽水／资源抽取、各类加工机、多产物、包装／解包、燃料发电与废料、Sink。枚举目标版本实际建筑类型，记录是否覆盖及原因。
- 受控验证一个固体配方、一个流体配方和一个电路；测试堵料、停电、增产、缓冲转移与远离玩家后生产，排除可见范围／流送造成的漏采。
- 验证电力总量、储能和分类数据，查清实际消耗／需求、实际发电／容量、增益及特殊消费者的区别。
- 明确回调是否在工厂线程、是否可能重复注册、是否父子路径双计；将真实数量对比写入证据。

**验收：** 固体／流体计数与实际操作一致，电力读数可与原生界面对照，精度已记录；关键原生机器均有实现路径。只有头文件证据时标为静态调查通过，不能放行正式游戏集成。

**失败出口：** 对拿不到真实值的类别写出缺口、尝试路径和最小调整建议，反馈整合 agent；不得默默改为库存差分／理论产能。

### T02 数据契约冻结

**负责范围：** 一个共享类型头文件及其必要实现；在 API_EVIDENCE.md 中补充契约映射。共享类型由本任务负责人独占。

**工作：** 将 PLAN.md 中的序列 ID、数量事件、电力快照、桶、查询、结果、保存版本变成实际类型；定义单位、精度、有效时间、未知值、零值、稳定资源 ID、窗口边界和错误状态。明确仅权威世界写入，但此时不添加联网代码。

**验收：** 一条固体事件、一条流体事件、一条电力快照和一个缺口可通过同一查询约定表达；累计量、平均功率与能量末值没有混淆；T03～T07 可按契约独立实现。草案阶段未经 UE 编译必须标注，T01 运行验证后再冻结。

### T03 有界历史与查询

**负责范围：** History 相关源文件及最小可运行算法检查；不编辑输入或 UMG。

**工作：**

- 先完成真实实现的事件累计及 1m 查询，再加 PLAN.md 的全部窗口、分级桶和 All。
- 根据活跃序列数测算内存／保存体积，确定桶参数；没有 UE 环境时核心算法可以使用标准 C++ 并由本地编译器运行同一实现。
- 实现数量守恒、功率时间积分、储能末值、有效覆盖和缺口；处理乱序／非法时间、暂停、桶边界、长间隔及粗桶查询范围。
- 查询点数有上限；不会因 1000h 或 All 分配与运行时长成正比的数组。缺失区间不能被压成零值。

**验收：** A06、A07、A08 的数学部分及 A11 的合成检查通过；至少覆盖不等长功率样本、多级桶交界、所有窗口、超过1000小时和一次保存数据往返。测试使用固定输入，不等待真实数百小时。

**交付证据：** 实际测试命令、累计量／能量期望值、容量测算、边界近似说明；不靠逐帧全历史重算。

### T04 物品与流体实际采集

**负责范围：** 生产采集源文件；子系统接线由整合 agent 处理。

**工作：** 将 T01 证据中的受支持接入点落到实际实现；统一 ID／单位；按类别在正确事件边界计数；实现权威检查、去重注册、停止世界清理和必要线程交接。覆盖新增、拆除、读档已有机器、配方更换及流送；不在 Widget 中扫描设备。

**验收：** A02～A05通过；覆盖矩阵中每个首版原生机器类型有结果；关窗时继续收集；错误路径不会影响游戏产出；跨线程访问和回调生命周期有依据。

### T05 电力采集与分组

**负责范围：** 电力采集源文件；复用 T02/T03，不建立第二套历史。

**工作：** 按合理频率从实际电力系统读取去重后的网络快照；形成世界总量、建筑类型组、储能充放电和异常网络数；验证网络合并／拆分、无电网、无储能、跳闸、增益和特殊负载。未分类量必须可解释。

**验收：** A08、A09通过；列表组和总值可核对；没有 MW／MWh 混用或储能双计；网络 ID 改变不会产生新的一份重复历史。

### T06 P 键与公共窗口

**负责范围：** 输入资产、本地窗口控制代码、公共顶部 UMG 资产；不要修改采集算法。

**工作：** 按锁定版本示例接入可重绑 Enhanced Input；实现 P／Esc／关闭、原生 UI 栈、焦点恢复、单实例窗口以及退出世界清理。顶部严格采用时间栏在标签栏上方，电力页也相同；初始可用明确标注的示例结果调布局。

**验收：** A01通过；九个时间按钮和三个标签均可操作；改键生效；输入 P 文字不会关窗；没有不断重建 Widget 或每帧查询全世界。截图证明布局，不以代码存在替代界面验证。

### T07 图表、列表与三个页面

**负责范围：** 共用图表控件、共用条目列表、三个页面及资源绑定；与 T06 使用同一 UI 负责人。

**工作：**

- 实现折线、坐标、单位、悬停、缺口、图例选择、恢复显示；同一绘图控件服务各页。
- 物品／流体双栏，电力当前概览＋三栏；宽屏条目可两列，小屏收窄但操作可达。
- 接入真实查询结果；搜索、排序与曲线筛选只影响展示；保持颜色与 ID 关联。
- 同时展示实际查询时间和覆盖不足；电力顶部当前值与下方窗口数据有清晰标注。
- 只在窗口打开时刷新展示，使用合理列表复用／裁剪，避免为每条线创建大量 Widget。

**验收：** A07展示部分和A12通过；三张实机截图分别与参考图结构对照；来自T04/T05的数字和T03查询一致；不存在发布时遗留的随机曲线／假数值。

### T08 历史随档保存与恢复

**负责范围：** 子系统保存链路、历史序列化及相应检查；与 T03 协调相同文件独占。

**工作：** 接入游戏保存生命周期，保存schema、累计、时钟、多级桶、All与覆盖；恢复前校验数据，处理旧schema／未知schema、损坏字段、缺失物品资源及从没有Mod的存档首次启动。保存时与采集更新保持一致快照，避免重复登记探针。

**验收：** A10、A11往返和A13通过；重启后统计不从零开始；读旧档不会连接未来数据；无法识别的未来schema不静默覆盖原数据。卸载再保存后的历史保留情况通过备份场景实测并写明。

### T09 单人验收和发布包

**负责范围：** 最终集成修复、构建配置、`docs/VALIDATION.md`、`docs/RELEASE.md`、实际Alpakit产物；跨模块修复先协调负责人。

**工作：**

- 在锁定的最新稳定环境跑 PLAN.md A01～A15，核实所有采集类别与所有时间按钮，不只测试铁板。
- 测量大工厂的开关窗口耗时、线程开销、内存和存档体积；检查连续运行、重复进出世界及日志噪声。
- Alpakit打包真实C++二进制与所需资产；验证插件元数据、SML依赖、游戏约束、版本、图标、资产引用及包内容。
- 清洁安装测试，并给出可复现构建步骤、安装步骤、版本范围、生产覆盖和已知问题。

**验收：** 单人验收表有逐项证据；真实安装包可加载；无开发机器绝对路径和编辑器依赖；既有游戏生产行为未改变。交付候选包与来源版本，公开上传交给T11。

### T11 GitHub 发行、SMR 分发与 SMM 管理验证

**负责范围：** GitHub公开源码和版本发行、RELEASE.md中的发布材料、ficsit.app Mod条目和版本信息（仅在获准发布后操作）、SMM验证记录。

**工作：**

- 按当前SMR文档准备名称、固定Mod Reference、作者信息、说明、图标、三页截图、版本包及真实兼容状态；作者和支持链接无法确定时作为待补字段，不编造。
- 验证公开GitHub仓库包含实际源码及必要自有源资产、用户确定的LICENSE、依赖说明和复现步骤；从干净clone验证构建。若用了LFS，要验证新clone能取得全部必要资产。
- 为发行源码创建对应语义版本tag及GitHub Release说明，记录构建提交和包来源；在SMR页面设置真实Source链接。不得将引擎、游戏资源、凭据、私人存档或未确认可再分发的参考图推送到公开仓库。
- 页面写明P默认键、可重绑、统计范围、安装后才开始采集、单人支持、存档和禁用限制。
- 先交付可审阅材料和候选包；当前规划不含公开发布动作。获得用户发布授权且账号可用后按SMR实际流程上传，记录真实页面URL、版本和审批／可见状态。
- 用干净SMM配置验证获取、依赖安装、启用、禁用、重启、再启用、卸载；然后发布／使用第二个合适版本验证升级保留键位及历史。无本地导入能力时不要虚构流程。
- SMM中可搜索到、可下载安装且版本匹配才算分发链通过；等待审核或没有账号仍属于待完成。

**验收：** A17通过，提供真实SMM版本、安装来源、截图／日志、两个Mod版本和存档升级结果；没有手工放DLL替代SMM安装。公开GitHub仓库URL、LICENSE、发行tag和干净clone验证齐全。此任务完成后才宣称已开源并可通过ficsit.app/SMM交付。

### T10 后续联机与专服

**负责范围：** 原生联网传输、权威子系统接线、客户端数据接入、服务端构建配置和联机验证；不重新实现统计算法。

**工作：**

- 仅主机／专服采集和保存，客户端请求并显示有界查询快照；原生RPC／RCO选择按对象所有权实测。
- 用户切换窗口时传范围和序列请求，限制点数、频率和序列数；不复制全部多年历史，不信任客户端上报生产事实。
- 明确关闭页面停止显示数据传输但服务端继续统计；大响应必要时有界分片，带请求代次防止旧结果覆盖新查询。
- 覆盖延迟加入、断线重连、主机退出、无玩家在线、版本不匹配、无UI专服和多个并发查看者。
- 按实际目标增加Windows／Linux服务端产物；更新SMM元数据及SMR兼容说明，不把单人构建自动标成专服支持。

**验收：** A16通过；同一时间窗口两客户端一致，不双计，不因客户端请求异常拖垮服务端；单人A01～A15关键路径继续通过。
